# Bank Marketing Subscription Prediction

A complete Python + MongoDB + PyMongo + scikit-learn project that predicts whether a bank client subscribes to a term deposit. The primary model is a Random Forest Classifier and the required evaluation metrics are Accuracy, Precision, Recall, and F1 Score.

## Dataset
Use the official UCI Bank Marketing dataset, `bank-full.csv` (45,211 rows; 17 columns including target `y`):
https://archive.ics.uci.edu/dataset/222/bank+marketing

The original dataset is not bundled because it should be retained from your own download. Copy `bank-full.csv` into `data/`. The import script expects semicolon-separated CSV data.

## Prerequisites
- Python 3.10+
- MongoDB Community Server running locally, or a MongoDB Atlas URI
- VS Code (recommended)
- Streamlit and Plotly (installed by `requirements.txt`)

## Setup (Windows PowerShell)
```powershell
# Run from the project root
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```
If PowerShell blocks activation, use `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal, then activate again.

## Run the project
1. Put `bank-full.csv` in `data/`.
2. Ensure MongoDB is running.
3. Import the dataset:
```powershell
python src/import_data.py
```
4. Explore MongoDB records:
```powershell
python src/query_data.py
```
5. Train and evaluate using data retrieved from MongoDB:
```powershell
python src/train_evaluate.py
```
6. Test a sample prediction:
```powershell
python src/predict_customer.py
```
7. Run the separate SMOTENC class-imbalance experiment:
```powershell
python src/smote_experiment.py
```
8. Start the interactive web application:
```powershell
streamlit run app.py
```
Open `http://localhost:8501`.

Generated results are saved in `outputs/`, charts in `outputs/charts/`, and the trained pipeline in `models/`.
The SMOTENC experiment writes its results and charts under `outputs/smote_experiment/`
and saves `models/random_forest_smote_model.joblib` without overwriting the baseline model.

## Streamlit application

The application provides Dashboard, Dataset Explorer, Data Analysis, Model
Performance, Model Comparison, Customer Prediction, Prediction History, and
About Project views through the sidebar. Customer browsing uses MongoDB
pagination and read-only queries, so the original customer collection is not
modified. Prediction records are written only to the separate
`PredictionHistory` collection.

The Customer Prediction page loads either existing Joblib pipeline and never
re-trains during a request. Both pipelines contain their required preprocessing.
The prediction probability is an estimate, not a guarantee. Dashboard and
analysis data use short-lived read-only caches; restart the app or wait for the
cache TTL after external database changes.

## Important methodology
- The target is `y` (`yes` = subscribed, `no` = not subscribed).
- The model excludes `duration`, because duration is only known after the call and can cause leakage in a pre-call prediction scenario.
- A stratified 80/20 split is used.
- Preprocessing is fitted inside a scikit-learn Pipeline, avoiding fitting encoders on the test data.
- Results are calculated at runtime; the report intentionally does not invent scores. Update the report's results table after running the model.

## SMOTENC class-imbalance experiment

The target is imbalanced: the supplied dataset contains 39,922 `no` records and
5,289 `yes` records. SMOTE creates synthetic minority examples, but ordinary
SMOTE after one-hot encoding can create fractional categorical indicators that do
not represent real categories. This experiment therefore uses SMOTENC: numeric
features are imputed, categorical features are imputed and ordinal-encoded, and
SMOTENC resamples the categorical feature positions using category-aware logic.
The Random Forest then trains on the resampled training data.

The 80:20 stratified split is made before fitting any transformer or sampler.
Only the training partition is passed through SMOTENC; the original test
partition remains untouched for both models. `duration` is excluded in both
experiments because it is known only after the call.

The measured results below were generated by `python src/smote_experiment.py`
from the MongoDB dataset. Yes is the positive class:

| Metric | Baseline Model | SMOTENC Model |
|---|---:|---:|
| Accuracy | 86.12% | 87.50% |
| Precision | 42.54% | 46.12% |
| Recall | 53.12% | 40.45% |
| F1-score | 47.25% | 43.10% |
| ROC-AUC | 80.22% | 78.87% |

SMOTENC did not improve subscriber detection for this run: recall fell from
53.12% to 40.45%, and F1-score and ROC-AUC also fell, although accuracy and
precision increased. The baseline model remains available at
`models/random_forest_model.joblib`; the new model is saved separately.
Classification reports, confusion matrices, comparison CSV, and charts are in
`outputs/smote_experiment/`.

## MongoDB schema
Database: `bank_marketing_db`
Collection: `customers`
Each customer is a document with the original dataset fields. MongoDB adds `_id`; the modelling script excludes it.
